# txt-to-excel

### ▶ [ลองตัวตรวจในเบราว์เซอร์](https://olay097056.github.io/txt-to-excel/)

วางข้อมูลของคุณเองลงไป หรือกดโหลดตัวอย่างสังเคราะห์ที่แถมมา ตรรกะการตรวจสอบ
พอร์ตมาจาก `txt_to_excel.py` ทีละบรรทัด ทำงานในเบราว์เซอร์ล้วน ไม่มีการอัปโหลดข้อมูล

---

อ่านไฟล์ export จาก**เครื่องรูดบัตร ETWIN** แปลงเป็น Excel ที่ระบายสีตามความน่าเชื่อถือ
พร้อมชี้จุดที่น่าจะผิด ให้คนตรวจแค่ 5 บรรทัดที่น่าสงสัย แทนที่จะต้องเพ่ง 2,700 บรรทัด
ที่หน้าตาเหมือนกันหมด

งานจริงที่มันทำคือตอบว่า **"เครื่องไหนกำลังมีปัญหา"**

เครื่องรูดบัตรที่เริ่มอ่านเลขเพี้ยนจะไม่บอกใคร ข้อมูลยังเข้ามาปกติ หน้าตาก็เหมือนเดิม
กว่าจะรู้ตัวก็อีกหลายสัปดาห์ ตอนมีคนมาถามว่าทำไมเวลาเข้างานไม่ตรง เครื่องมือนี้อ่าน
export จัดกลุ่มความเสียหายตามเครื่อง แล้วชี้ชื่อเครื่องที่มีปัญหาออกมาตรงๆ:

```
รวม 60 รายการ | ปกติ 55 | สงสัย 1 | ผิด 4
เครื่องที่มีปัญหา: 01, 02, 03, 04, 06
```

แต่ละบรรทัดที่ export ออกมายาว 20 ตัวอักษรพอดี:

```
04  2026  08  08  0231  029405
──  ────  ──  ──  ────  ──────
เครื่อง ปี  เดือน วัน  เวลา    EN
(2)  (4)  (2) (2)  (4)   (6)
```

`เครื่อง` คือหมายเลขเครื่องรูดบัตร `EN` คือเลขบัตรหรือรหัสพนักงาน
ส่วน 4 ฟิลด์ตรงกลางคือเวลาที่รูด

## จุดที่น่าสนใจ: ตรวจ 2 ชั้น

การแยกข้อความความกว้างคงที่เป็นเรื่องง่าย ปัญหาจริงคือ**ข้อมูลที่เสียมักหน้าตาถูกต้อง
ทุกอย่าง** เครื่องอ่านพลาดเปลี่ยนเลขตัวหนึ่งเป็นอีกตัวหนึ่ง ผลลัพธ์ก็ยังเป็นตัวเลข
6 หลักในตำแหน่งที่ถูก การตรวจจึงแยกเป็น 2 ชั้นที่เป็นอิสระต่อกัน

**ชั้นที่ 1 กฎตายตัว (สีแดง)** จับค่าที่เป็นไปไม่ได้เชิงโครงสร้าง ได้แก่ ฟิลด์ที่มี
อักขระไม่ใช่ตัวเลข, ปีนอกช่วง 2000–2099, เดือนนอกช่วง 1–12, วันที่ไม่มีอยู่จริง
ในเดือนนั้น (คิดปีอธิกสุรทินด้วย), เวลาที่ผิดรูป และบรรทัดที่ยาวไม่เท่ากับ 20

อักขระควบคุมที่ Excel เขียนลงไฟล์ไม่ได้ (เจอบ่อยในไฟล์จาก OCR และเครื่องสแกน)
จะถูกลบทิ้งก่อนแยกฟิลด์ ไม่ปล่อยให้ export พังทั้งไฟล์

**ชั้นที่ 2 ความถี่รายเครื่อง (สีเหลือง)** เครื่องมือเรียนรู้แยกทีละเครื่องว่าปกติ
เครื่องนั้นส่งค่าอะไรออกมา เครื่องที่รายงานเดือน `08` อยู่ 99% แล้วโผล่ `09`
มาครั้งเดียว น่าจะอ่านพลาด ทั้งที่ `09` เป็นเดือนที่ถูกต้องสมบูรณ์และชั้นที่ 1
ไม่มีวันจับได้

การทำแบบนี้*แยกรายเครื่อง*แทนที่จะรวมทั้งไฟล์ คือสิ่งที่เปลี่ยนคำตอบจาก
"ไฟล์นี้มี error" ให้เป็น "เครื่อง 03 ต้องไปดูแล้ว"

ความถี่ใช้กับ ปี เดือน วัน **เท่านั้น** เวลากับ EN ตัดออกโดยตั้งใจ เพราะสองอันนี้
เกือบทุกรายการมีค่าไม่ซ้ำกัน ถ้าเอาไปจับด้วยจะเตือนทุกบรรทัดจนกลบของจริงหมด
**การรู้ว่าฟิลด์ไหน*ไม่ควร*เอาสถิติไปจับ คือส่วนที่ทำให้เครื่องมือนี้ใช้งานได้จริง**

ไฟล์ผลลัพธ์ระบายสีแต่ละแถวตามผลตรวจ และบอกรายแถวว่าฟิลด์ไหนผิด เพราะอะไร

## วิธีใช้

```bash
pip install openpyxl
```

แบบ GUI วางข้อความลงไปตรงๆ หรือ import ไฟล์ก็ได้:

```bash
python txt_to_excel.py
```

แบบ CLI:

```bash
python txt_to_excel.py --file sample_data.txt --out result.xlsx
```

ลองกับไฟล์ตัวอย่างที่แถมมา ในนั้นมีความผิดตามกฎตายตัว 4 จุด และความผิดปกติ
เชิงความถี่อีก 1 จุด:

```
รวม 60 รายการ | ปกติ 55 | สงสัย 1 | ผิด 4
```

## หมายเหตุ

- `sample_data.txt` เป็นข้อมูลที่สร้างขึ้น ไม่ใช่ของจริง ไฟล์ export จาก ETWIN ของจริง
  มีรหัสเครื่อง เวลาที่รูด และเลข EN ที่เป็นของคนจริง จึงถูก gitignore ไว้ทั้งหมด
- ไฟล์ `.exe` สำหรับ Windows มาจากการ build ด้วย PyInstaller (~30 MB)
  ไม่ได้เก็บใน version control ถ้าต้องการให้ build จากซอร์สเอง

## เทคโนโลยีที่ใช้

Python 3, Tkinter สำหรับ GUI, openpyxl สำหรับสร้างไฟล์ Excel ไม่มี dependency อื่น
