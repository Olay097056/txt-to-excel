# txt-to-excel

อ่านไฟล์ export ดิบจาก**เครื่องรูดบัตร ETWIN** แปลงเป็นไฟล์ Excel ที่ระบายสี
ตามความน่าเชื่อถือ พร้อมชี้จุดที่น่าจะผิด — เพื่อให้คนตรวจแค่ 5 บรรทัดที่น่าสงสัย
แทนที่จะต้องเพ่ง 2,700 บรรทัดที่หน้าตาเหมือนกันหมด

งานจริงที่มันทำคือตอบคำถามว่า **"เครื่องไหนกำลังมีปัญหา"** เวลาเครื่องรูดบัตร
เริ่มอ่านตัวเลขตกหรือเพี้ยน มันไม่ประกาศให้รู้ ข้อมูลยังไหลเข้ามาเรื่อยๆ
ยังหน้าตาเหมือนข้อมูลปกติ แล้วปัญหาจะโผล่อีกทีตอนที่มีคนพบว่าเวลาเข้าออกงาน
ของตัวเองไม่ตรงเมื่อผ่านไปหลายสัปดาห์แล้ว เครื่องมือนี้อ่าน export
จัดกลุ่มความเสียหายตามเครื่อง แล้วชี้ชื่อเครื่องที่กำลังมีปัญหาออกมาตรงๆ:

```
รวม 60 รายการ | ปกติ 55 | สงสัย 1 | ผิด 4
เครื่องที่มีปัญหา: 01, 02, 03, 04, 06
```

แต่ละบรรทัดที่ export ออกมายาว 20 ตัวอักษรพอดี:

```
04  2026  08  08  0231  029405
──  ────  ──  ──  ────  ──────
เครื่อง ปี  เดือน วัน  เวลา    EN
(2)  (4)  (2) (2)  (4)   (6)
```

`เครื่อง` คือหมายเลขเครื่องรูดบัตร `EN` คือเลขบัตร/รหัสพนักงาน
ส่วน 4 ฟิลด์ตรงกลางคือเวลาที่รูด

## จุดที่น่าสนใจ: การตรวจจับ 2 ชั้น

การแยกข้อความความกว้างคงที่เป็นเรื่องง่าย ปัญหาจริงที่เครื่องมือนี้แก้คือ
**ข้อมูลที่เสียมักหน้าตาถูกต้องทุกประการ** — เครื่องสแกนอ่านพลาด เปลี่ยนเลขตัวหนึ่ง
เป็นอีกตัวหนึ่ง ผลลัพธ์ก็ยังเป็นตัวเลข 6 หลักในตำแหน่งที่ถูกต้องอยู่ดี
การตรวจสอบจึงทำเป็น 2 ชั้นที่เป็นอิสระต่อกัน:

**ชั้นที่ 1 — กฎตายตัว (ทำเป็นสีแดง)** ค่าที่เป็นไปไม่ได้เชิงโครงสร้าง: ฟิลด์ที่มี
อักขระไม่ใช่ตัวเลข, ปีนอกช่วง 2000–2099, เดือนนอกช่วง 1–12, วันที่ไม่มีอยู่จริง
ในเดือนนั้น (คิดปีอธิกสุรทินด้วย), เวลาที่ผิดรูป, บรรทัดที่ยาวไม่เท่ากับ 20
ส่วนอักขระควบคุมที่ Excel เขียนลงไฟล์ไม่ได้ — ของแถมประจำจาก OCR และเครื่องสแกน —
จะถูกลบทิ้งก่อนแยกฟิลด์ แทนที่จะปล่อยให้การ export พังทั้งไฟล์

**ชั้นที่ 2 — ความถี่รายเครื่อง (ทำเป็นสีเหลือง)** เครื่องมือเรียนรู้แยกทีละเครื่องว่า
ปกติเครื่องนั้นส่งค่าอะไรออกมา เครื่องที่รายงานเดือน `08` อยู่ 99% ของรายการทั้งหมด
แล้วโผล่ `09` มาครั้งเดียว มีแนวโน้มว่าอ่านพลาด ทั้งที่ `09` เป็นเดือนที่ถูกต้อง
สมบูรณ์และชั้นที่ 1 ไม่มีวันจับได้ การทำแบบนี้*แยกรายเครื่อง*แทนที่จะรวมทั้งไฟล์
คือสิ่งที่เปลี่ยนคำตอบจาก "ไฟล์นี้มี error" ให้เป็น "เครื่อง 03 ต้องไปดูแล้ว"

การวิเคราะห์ความถี่ใช้กับ ปี เดือน วัน **เท่านั้น** ส่วนเวลากับ EN ถูกตัดออกโดยตั้งใจ
เพราะมันมี cardinality สูง — เกือบทุกรายการมีค่าไม่ซ้ำกัน — เกณฑ์ "ผิดปกติสำหรับ
เครื่องนี้" จึงจะเตือนทุกบรรทัดและกลบของจริงจนหมด **การรู้ว่าฟิลด์ไหน*ไม่ควร*
เอาสถิติไปจับ คือส่วนที่ทำให้การตรวจสอบนี้ใช้งานได้จริง**

ไฟล์ผลลัพธ์จะระบายสีแต่ละแถวตามผลตรวจ และระบุรายแถวว่าฟิลด์ไหนผิด เพราะอะไร

## วิธีใช้

```bash
pip install openpyxl
```

แบบ GUI — วางข้อความลงไปตรงๆ หรือ import ไฟล์ก็ได้:

```bash
python txt_to_excel.py
```

แบบ CLI:

```bash
python txt_to_excel.py --file sample_data.txt --out result.xlsx
```

ลองกับไฟล์ตัวอย่างสังเคราะห์ที่แถมมา ซึ่งมีความผิดตามกฎตายตัว 4 จุด
และความผิดปกติเชิงความถี่ 1 จุด:

```
รวม 60 รายการ | ปกติ 55 | สงสัย 1 | ผิด 4
```

## หมายเหตุ

- `sample_data.txt` เป็นข้อมูลที่สร้างขึ้น ไม่ใช่ของจริง — ไฟล์ export จาก ETWIN ของจริง
  มีรหัสเครื่อง เวลาที่รูด และเลข EN ที่เป็นของคนจริง จึงถูก gitignore ไว้ทั้งหมด
- ไฟล์ `.exe` สำหรับ Windows เป็นผลจากการ build ด้วย PyInstaller (~30 MB)
  ไม่ได้เก็บใน version control — ถ้าต้องการให้ build จากซอร์สเอง

## เทคโนโลยีที่ใช้

Python 3, Tkinter สำหรับ GUI, openpyxl สำหรับสร้างไฟล์ Excel ไม่มี dependency อื่น
